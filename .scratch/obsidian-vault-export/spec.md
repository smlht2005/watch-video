# Obsidian 知識庫匯出（含 Threads 圖文入口、知識點、人選連結）

## Problem Statement

我用 `/watch-archive` 把影片與貼文歸檔成圖文報告（Word／Markdown），但這些成果沒有進入我的 Obsidian：

- 報告是「一支影片一份」的長文件，含逐字稿與逐段截圖，不適合當知識庫筆記，也沒有可累積的連結網路。
- 我在 Obsidian 真正想留下的是「知識點」（可獨立成立的概念、方法、判斷標準），不是整份逐字稿；萃取與取捨應該由我確認，而不是全部自動塞進去。
- 若連結靠語義相似度自動產生，只會得到「看起來相關、其實沒有關係」的連線；我要的是每條連結都有關係說明、經我確認。
- 我常分享的 Threads／IG 圖文輪播貼文（沒有影片）會讓 `/watch-archive` 直接失敗（`yt-dlp` 不支援），我得手動抓圖、建資料夾；曾因只看主頁而漏掉第 9、10 頁。
- 我的 session 在雲端，碰不到本機 vault；我也不想讓工具弄亂我個人 vault 裡原有的筆記。

## Solution

歸檔完成後多一個可選的匯出步驟：把每份歸檔整理成 Obsidian 筆記，只放「我確認過」的內容。

- 影片（或圖文貼文）變成一篇筆記：屬性、摘要、思維導圖、知識點清單、已確認連結、補充資料。
- 每個知識點是獨立的原子筆記，附一句原文引用、出處（影片時間或第 N 頁）、「作者／講者主張，未查證」標示，以及指回影片筆記的出處連結。
- 概念連結只取自我確認過的清單，每條寫明關係類型與說明；Claude 只能提案成「候選」，我確認後才匯出。
- 貼 Threads 貼文網址給 `/watch-archive` 即可自動抓回本文與全部頁面圖並建好骨架，頁面文字仍由 Claude 看圖抄錄。
- 預設寫進 repo 內專用的 vault（用 git 傳到我本機）；也可指定我自己的 vault，此時全部收進其下 `watch-archive/` 子資料夾，不動我其他檔案。

## Implementation Decisions

- **兩個新手寫檔（與 `summary.md` 同資料夾，重跑歸檔不覆蓋）**：
  - 連結清單：分「已確認」「候選」兩區；每行是 `[[概念]]` 後接全形「｜」、關係類型、冒號、說明。
  - 知識點清單：分「已確認」「候選」兩區；每個知識點一個小標題區塊，含出處、引文、說明、標示，以及零到多條帶關係的連結。
  - 兩者都只匯出「已確認」區。沒有分區標題的檔案整份視為候選（警告、不匯出）。這是為了強制「使用者確認」這一步不被跳過。
- **兩種連結分開處理**：出處連結（知識點→影片筆記、影片筆記→知識點、影片筆記→SOP 筆記）由程式機械產生；概念連結只能來自已確認清單。`keywords` 只當 tags，不轉成連結；不使用語義相似度產生任何連結。
- **關係類型沿用貼文的分類**（上位概念、舉例、互補、反例與侷限、歷史脈絡、實際應用、另一個學科），但不強制白名單，只強制「有類型且有說明」。
- **匯出器輸出結構**：影片筆記（依領域資料夾）、知識點筆記（獨立資料夾）、SOP 筆記（有 SOP 時）、附件（以影片 ID 分組、相對路徑）、索引（領域清單、知識點依來源分組、待建立節點與被誰連結）。圖片範圍只含思維導圖、圖文貼文頁面圖與 SOP 步驟圖，不複製影片截圖。
- **屬性與標記**：每個產生的檔案帶 `generated_by: watch-archive` 與影片 ID；重匯只覆蓋帶此標記且影片 ID 相符的檔案，同名但非我們產生的檔案不覆蓋（另存加 ID 後綴）；標題或領域改變時清掉同影片 ID 的舊產生檔。
- **知識點命名衝突**：不同影片的同名知識點各存一份（加 ID 後綴），不自動合併；合併由人工處理。
- **傳輸與位置**：預設 vault 位於 repo 內並 commit（git 傳輸）；`--vault <路徑>` 指向使用者自己的 vault 時，所有輸出（含索引與附件）收進該 vault 下的 `watch-archive/`，不動 vault 其他部分。
- **匯出為手動步驟**：在重建報告之後執行；不在歸檔或建報告時自動觸發。逐字稿不進筆記（只留在報告）；貼文本文因短，可整段進筆記的補充資料。
- **Threads 圖文入口**：
  - 判斷：網址主機為 Threads 時先嘗試圖文流程；頁面帶影片標記則回到影片流程；抓取失敗印警告並回到影片流程。
  - 取得：分享連結解析為正式貼文網址；主頁取本文（`og:description`）與作者；貼文網址加 `/embed` 取全部頁面圖（排除頭像，依序去重）。不使用 cookies 或登入。
  - 骨架：圖片下載為依序命名的頁面圖；`meta.json` 帶 `media_type: carousel`、平台 Threads、貼文 ID 為影片 ID、頁數為長度、轉錄來源為「圖片文字（逐頁人工抄錄）」；`transcript.md` 與 `summary.md` 放待補範本；貼文本文逐字寫入補充資料。
  - 以頁碼代替時間碼（第 N 頁＝`00:0N`），使既有的報告、截圖對應與思維導圖機制不變。
  - 既有資料夾重跑時：只補缺的頁面圖並更新來源欄位；手寫檔與手寫的 `meta.json` 欄位（標題覆寫、關鍵字、slides）保留。
- **報告對圖文貼文的呈現**：標題為「第 N 頁」、不顯示時間範圍，表頭用「頁數」。
- **文件**：新增 skill 參考檔（4e 連結、4f 知識點、5b 匯出、圖文貼文流程）；`SKILL.md` 步驟表與要點、`CLAUDE.md` 硬規則、`README`、`deliver.md` 同步更新；`GLOSSARY.md` 與新領域詞典已完成。
- **IG 貼文**：不在本次範圍；等實際遇到再驗證是否有同樣的 `/embed` 可用。

- **手寫檔格式（契約，審查補）**：
  ```
  # 知識點                          # 連結
  ## 已確認                         ## 已確認
  ### 知識點標題                    - [[概念]]｜關係類型：說明
  - 出處：第 5 頁 或 03:12          ## 候選
  - 引文：「原文一句」              - [[概念]]｜關係類型：說明
  - 說明：一兩句話
  - 標示：作者主張，未查證
  - 連結：[[概念]]｜關係類型：說明   （可多條）
  ## 候選
  ### …
  ```
  兩個分區標題之外的 `##` 標題會結束目前分區；知識點標題要唯一（同一影片內重名視為錯誤並警告）。
- **預設標示（審查補）**：知識點未填「標示」時，來自影片或貼文的一律補上「講者／作者主張，未查證」（對應 `CLAUDE.md` 硬規則）；只有整理者自己寫的補充才可標「整理者補充」。
- **引文核對（審查補）**：知識點的引文若在該資料夾的 `transcript.md` 或 `supplement.md` 找不到對應字串，匯出時警告（不擋匯出），防止轉述被當成原話。
- **筆記狀態（審查補）**：影片筆記只在有已確認連結或已確認知識點時，`status` 為 `reviewed`，否則 `unreviewed`；知識點筆記一律 `confirmed`。
- **Threads 抓取的安全邊界（審查補）**：圖片只接受 https 且主機屬 Instagram／Meta CDN（`cdninstagram.com`、`fbcdn.net`）；每頁下載有逾時與大小上限，頁數上限（例如 30）；超過或不符者略過並警告，不擴散到任意網址。
- **平台命名（審查補）**：新歸檔的 Threads 貼文平台記為 `Threads`；先前以 `Web` 歸檔的 Threads 貼文維持原樣，不回填。

## Testing Decisions

- **好測試的標準**：只驗外部行為與輸出檔案，不測內部函式的呼叫方式；用暫存資料夾與假資料，不連網、不依賴真實 vault。
- **接縫 1（現成）— 匯出**：`export(歸檔資料夾, vault)` 加 `write_index(vault)`，從歸檔資料夾到 vault 檔案樹。涵蓋：屬性與連結內容、已確認／候選分流、缺關係被拒絕、無分區標題一律當候選、知識點原子筆記的內容與出處連結、`--vault` 子資料夾（不碰根目錄既有檔案）、重匯保留使用者檔案、改名清舊檔、同名衝突不覆蓋（含使用者自己的筆記）、SOP 筆記圖片路徑改寫、圖文貼文頁面圖與相對路徑、索引含待建立節點與知識點。
- **接縫 2（新，只在網路邊界）— Threads 入口**：`archive_threads_post` 以可注入的「抓取」替身接錄好的 HTML 樣本。涵蓋：骨架正確（頁面圖數量、`carousel` 標記、補充資料含本文、頭像被排除）、重跑不覆蓋手寫檔、影片貼文回到影片流程（回傳未處理）、登入牆／無圖片／網路失敗各自印出明確錯誤並回到影片流程、分享連結與正式連結得到同一個資料夾。
- **沿用既有**：報告對圖文貼文的標題與頁數呈現已有測試，不重複。
- **前例**：`tests/test_obsidian_export.py` 的暫存資料夾與替換 `ROOT`／`OUT_ROOT` 的做法；`tests/test_watch_archive.py` 的 `BuildWithSop` 夾具。
- **注入點（審查補）**：Threads 入口除了「抓頁面」，還必須能替換「下載圖片」，測試才不會連網。
- **既有失敗**：`test_clip_check` 有一項在雲端環境失敗，與本功能無關，不在本 spec 範圍內修。

## Acceptance Criteria（審查補）

1. 對示範貼文（Threads 分享連結）執行 `/watch-archive`，得到 10 頁圖、貼文本文與骨架資料夾；重跑不改動任何手寫檔。
2. 完成摘要、逐頁抄錄、`links.md`、`knowledge.md` 並由使用者確認後，匯出的 vault 含：1 篇影片筆記、使用者確認的每個知識點各 1 篇、附件、索引（含待建立節點）。

5. 重匯兩次結果相同；使用者自己加的筆記與圖片仍在。

## Out of Scope

- 以語義相似度或關鍵字自動產生連結（刻意排除）。
- 知識點的自動萃取而不經確認；自動合併跨影片的同名知識點。
- 把逐字稿全文放進 Obsidian 筆記。
- Instagram、Facebook 等其他平台圖文貼文的自動抓取（IG 待驗證後再議）。
- 登入、cookies、繞過登入牆、OCR 自動辨識圖上文字（文字由 Claude 看圖抄錄）。
- 雙向同步（從 Obsidian 改回 `watch-output/`）；Obsidian 外掛、Dataview 查詢範本。
- 修復既有的 `test_clip_check` 失敗。
