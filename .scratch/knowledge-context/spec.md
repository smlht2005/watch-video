# 知識點筆記：補前後文、出處連到原段落

## Problem Statement

Obsidian 的知識點筆記（`obsidian-vault/知識點/*.md`）讀起來太單薄：

- `說明` 只有一句話，脫離影片後看不出講者在什麼情境、為什麼這麼說。
- 引文下方的出處只是純文字 `— 10:37`，點不下去；要回頭看原段落的截圖與逐字稿，得自己打開影片筆記往下捲。
- 引文前後講了什麼完全看不到，無法判斷引文有沒有被斷章取義。

## Solution

1. **出處變成段落連結**：`— 10:37` 改為連到影片筆記中「包含 10:37 的那一段」（`[[影片筆記#投影片 N：標題（開始–結束）|10:37]]`），點了直接跳到該段的截圖與逐字稿。YouTube 另附「▶ 原影片 10:37」（`&t=637s`）；其他平台不支援時間參數就省略。
2. **自動前後文**：以出處時間為中心，取 `transcript.md` 前後各 30 秒（最多 12 行）的逐字稿，放進預設收起的 callout `> [!quote]- 前後文（起–迄）`，每行保留 `[mm:ss]`，含引文的那一行加粗。外語影片有 `transcript.zh.md` 時只放中譯。
3. **說明補寫**：每個已確認知識點的 `說明` 改寫成 2–4 句，交代情境、理由與例子；寫在各影片的 `knowledge.md`，維持「已確認」，PR 前給使用者改前改後對照確認。規則寫進 `obsidian-4e.md`。

## User Stories

1. 作為讀知識點的人，我點出處時間就跳到影片筆記的那一段，看到截圖與完整逐字稿。
2. 作為讀知識點的人，我展開「前後文」就看到引文前後 30 秒的原話，不必離開筆記。
3. 作為讀知識點的人，`說明` 本身就讓我知道講者在什麼情境下、為什麼這樣主張。
4. 作為 YouTube 影片的讀者，我可以一鍵回到原影片的那個時間點。
5. 作為圖文貼文（Threads）的讀者，出處「第 N 頁」連到該頁段落，前後文是該頁抄錄全文。

## Implementation Decisions

- **段落對應**：出處時間 `t` 落在 `slides[i].start ≤ t < slides[i+1].start` 的那一段；錨點用匯出程式實際產生影片筆記段落標題的同一個函式組出，不寫死「投影片」字樣（日後改名不會斷）。沒有 `slides`（退回逐畫面）時，連到影片筆記本身。
- **前後文錨點用時間、不用字串比對**：引文常跨行。引文在視窗內任一行（或相鄰兩行串接）出現時，該行加粗；找不到引文也照樣顯示前後文，但不加粗。
- **不放前後文的情況**：出處沒有時間／頁碼、引文出自 `supplement.md`（畫面文字，逐字稿找不到且 supplement 找得到）、或逐字稿不存在。此時只保留段落連結。
- **圖文貼文**：出處 `第 N 頁` → 連到第 N 頁段落；前後文 = 該頁的 `transcript.md` 抄錄全文。
- **外部時間連結**：只限 `platform == YouTube`，以 `meta.json.url` 加 `t=<秒>s`；其他平台不加。
- **說明補寫**：Claude 改 `knowledge.md` 的 `說明`，不動 `引文`、`出處`；影片主張照舊標「講者／作者主張，未查證」。
- **不在範圍**：「投影片 N」段落標題改名（另開 issue）；新增知識點；連結（`links.md`）內容。

## Testing Decisions

`tests/test_obsidian_export.py` 新增：
- 出處時間對到正確段落（段首、段中、最後一段、早於第一段）。
- 前後文擷取 ±30 秒、上限 12 行、引文行加粗、跨行引文。
- 引文只在 `supplement.md` → 無前後文、仍有段落連結。
- 圖文貼文 `第 N 頁` → 連到該頁、前後文為該頁全文。
- YouTube 有 `&t=`／`?t=`，TikTok 等沒有外部時間連結。
- 外語影片有 `transcript.zh.md` 時前後文用中譯。
PR 前跑全套測試。

## Out of Scope

- 段落標題「投影片 N」改名（訪談／實拍影片讀起來怪）→ 另開 issue。
- 知識點的出處圖、連結格式不變。
