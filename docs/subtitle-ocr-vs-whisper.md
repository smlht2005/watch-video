# 畫面字幕 OCR vs Groq Whisper 轉錄：比較與做法

> 來源：2026-10-13／14 歸檔會性法師《大佛頂首楞嚴經》第103集（YouTube `kvsrMirvdDQ`，74 分鐘）時的實作經驗。
> 該片逐句燒入字幕，我用 OCR 把字幕全部抽出，與 Groq Whisper 逐字稿逐行比對校稿。

> **使用範圍**：OCR 很費時（74 分鐘約一小時），所以**限定佛經講解／講經座，且影片有逐句燒入字幕**才使用；其他影片（含有字幕的一般影片）不跑，改靠詞典與截圖校稿。

## 一句話結論

預設做法是兩者互補：Groq 負責完整語音與時間戳，OCR 負責校正人名、書名、術語，兩邊有差異時以字幕為準，但保留 Groq 的口語。

**例外：符合下面「字幕為底稿」條件的佛學影片，整份改以字幕為底稿**（第097集起），Whisper 只借時間戳並留作原話備份。條件不符時，維持互補，OCR 字幕不取代 Groq 轉錄。

## 比較

| 面向 | Groq Whisper 轉錄 | OCR 抽燒入字幕 |
|---|---|---|
| 適用範圍 | 任何有聲音的影片 | 只有畫面真的燒入字幕才行（沒有字幕就派不上用場） |
| 準確度 | 專有名詞、佛學詞誤聽多：圓通→遠通、葛藤→歌藤、阿難→歐南、照寮元→趙寮元、獅頭山→石頭山；這支校出數百處 | 文字基本是正確原文，人名、書名、引文都對（逗機、許止淨、徑山、古鼎） |
| 完整性 | 會整段漏轉（這支漏 17 分鐘，補漏時遇 HTTP 429）；片頭片尾會編出不存在的句子 | 無漏轉、無幻覺 |
| 忠實度 | 逐字還原口語（語助詞、口誤、重複），可去語助詞後保留 `transcript.raw.md` 原話 | 字幕是整理過的書面語：省略「呢啊」「注意哦」，會改寫句子，不是原話 |
| 時間戳 | 每句秒級時間戳，可直接進報告 | 取樣間隔 2 秒，只能對到約 2 秒；換行與跨句會對不齊 |
| 自身錯誤 | 同音字、斷句、簡繁 | v4 模型的繁體誤判（眾→罪、從→筱、遍→编、竟→竞、薩→隆、祂→弛、偈→偶，OpenCC 救不了）與同音混淆（異→昊、正脈→正服），「慍」常被丟掉；改用 v5 後這類誤判大幅減少；字幕本身也可能有錯，沒有第三來源可驗證 |
| 成本與速度 | 一次呼叫、數分鐘 | 74 分鐘取 2215 條字幕列，單程序約 1.8 秒一條，單程序要一小時以上（這次開 7 個程序平行） |
| 費用與隱私 | 要上傳音訊、會被限流（429） | 本機執行、免費，只吃 CPU |

## 這次的實際教訓

- 我先前靠上下文**推測**的專有名詞，有好幾個猜錯，都是字幕糾正的：趙寮元→**照寮元**、古頂→**古鼎**、晉山→**徑山**、徐子靖→**許止淨**、小繩→**小香**、投機→**逗機**、恭念→**一念**。校稿遇到不確定的專名，優先找畫面字幕，不要只靠上下文。
- 字幕不是原話，所以一般情形不要用字幕整句覆蓋逐字稿；只取差異處的用字，保留口語（符合「字幕為底稿」條件者例外，見下節）。
- OCR 輸出有簡繁／同音雜訊，每處差異要人工判斷，不能全自動套用。

## 字幕為底稿（佛學；第097集起）

使用者確認：佛學影片的燒入字幕是**編修過**的，專有名詞與引文比 Whisper 聽寫可靠；第097集的 Whisper 因口音錯很多（「閃士士」「文師修」「血脫」），另有 11 處 20–30 秒漏轉與片頭片尾幻覺，字幕卻連續涵蓋全片。所以字幕可以直接當逐字稿底稿，不必先用 Whisper 寫稿再用字幕改回來。

**條件（三項都要成立，先量再決定）**

| 項目 | 門檻 | 第097集實測 |
|---|---|---|
| 字幕涵蓋 | 合併後的字幕事件涵蓋秒數 ÷ 影片長度 ≥ 95% | 4320 ÷ 4407 秒＝98% |
| OCR 雜訊 | 簡轉繁後仍含簡體字的事件 < 1% | 3 ／ 1075 句 |
| 可對齊 Whisper | 字幕句在 ±20 秒內的 Whisper 文字中找得到對應（涵蓋比例 ≥ 0.4）≥ 90% | 94%（≥ 0.6 者 86%；對得上的句子時間偏移中位數 1 秒、90% 在 4 秒內） |

量法：`merge_events` 取得字幕事件，逐句與 Whisper 同一時間窗用 `difflib.SequenceMatcher` 算涵蓋比例。其他領域、字幕未編修、或條件不符時，不採用，維持前面的互補做法。

**做法**

1. 先備份 `transcript.md` 成 `transcript.whisper.md`（原話備份，不改）；`transcript.raw.md` 照舊。
2. 字幕簡轉繁（`to_traditional`）後，每個字幕事件一行；字幕結束後的片尾字卡亂碼（OCR 出現亂碼的最後幾個事件）丟掉；0:00 到第一句字幕之間若講者有說話，用 Whisper 補。
3. 時間戳＝字幕事件起點加「局部偏移」：先找出與 Whisper 行相符度 ≥ 0.5 的事件，算「Whisper 行起點 − 字幕起點」，每句取前後 8 個相符事件偏移的中位數；順序不得倒退，沒有相符事件的用字幕自己的時間（約 ±3 秒）。
4. 校稿照常兩輪：OCR 同音／形近字（雨→兩、昆→毘、鎮→鑪…）用 Whisper 同一時間窗交叉驗證後批次替換；成對的《》〈〉補齊；最後用 Read 從頭到尾逐行重讀。拿不準的記進 `known_asr_errors` 標「推測」並走 `clip_check --wait-confirm` 聽音確認。
5. **字幕漏掉的短句**：字幕每 3 秒取樣，閃過的短句、沒打字幕的插話抓不到。列出 Whisper 中被字幕涵蓋比例 < 0.45 的行，人工判斷：確實是講者說的教義順序（例如十二因緣還滅門整串）就依原話補回並記進 `known_asr_errors`；單純插話不補（第097集約 40 句，原話在 `transcript.whisper.md`）。
6. `meta.json`：`transcript_source` 寫 `subtitle OCR (PP-OCRv5 mobile)`、`transcript_timing` 寫 `subtitle time + local offset to whisper (groq)`、`video_type: "lecture"`；字幕 OCR 全文存 `ocr.json`。重跑 `watch_archive.py` 會覆蓋 `transcript.md`，要重做這幾步。
7. `index.md` 的轉錄來源欄改成字幕 OCR。

**限制**

- 字幕稿**沒有標點**、每行是 3–6 秒的短句；語助詞與口誤已被字幕整理掉，所以沒有去語助詞與口吃整理這兩步（`clean_fillers.py`、`stutter_check.py` 不跑）。
- 時間戳精度不如 Whisper，需要精確時間的步驟（`clip_check` 剪聽音確認、截圖對齊）要多留前後幾秒。
- 字幕本身可能有錯，沒有第三來源驗證時仍要標「推測」並請使用者聽音確認。

## 做法（`scripts/subtitle_ocr.py`）

環境：Windows，OCR 用 [RapidOCR](https://github.com/RapidAI/RapidOCR)（`rapidocr-onnxruntime`）裝在獨立 venv，不動系統 Python；`probe`／`run` 用該 venv 的 python，`compare` 只需 opencc，用一般 python。

**模型**（`--model`）：預設 `v5` ＝ PP-OCRv5 **mobile** 中文辨識（16 MB，Hugging Face `twmht/ppocr_v5_mobile`，首次執行自動下載到 `~/.cache/watch/ppocrv5-mobile`），偵測沿用 RapidOCR 內建 v4。`v5-server` ＝ 同一代的 server 版（84 MB，`monkt/paddleocr-onnx`）；`v4` ＝ RapidOCR 內建，保留給舊 ocr.json，`compare --model v4` 會套用固定誤判對照表。

**為什麼預設改成 mobile**（第097集追蹤 `[trace]`）：server 版每張約 9.5 秒，其中辨識 `rec` 占約 8 成（單張 1.5–43 秒，隨 CPU 供電、散熱與優先權劇烈波動）；mobile 版辨識只要 0.0–0.3 秒。第104集 10 張 v4 誤判的字幕列，mobile 與 server 同樣讀對（眾、從、麼、圓、門、漢），mobile 還多讀對「顯示」；兩者都讀不對「遍於」（讀成偏／編），仍要靠人工。mobile 的輸出字與字之間不夾空格。

1. 下載影片（`yt-dlp -f 136` 之類的 720p 視訊即可，放暫存區、不入庫）。
2. `python scripts/subtitle_ocr.py probe <video>`：抽 12 張畫面 OCR，過半有字就判定有燒入字幕，順便印出每張讀到的字；字幕位置不同時用 `--crop W:H:X:Y` 調整（預設是畫面下方 18%、左側 82%，避開右側直排標題）。
3. `python scripts/subtitle_ocr.py run <video> --out ocr.json --workers 1 --every 3 --background`：每 `--every` 秒（預設 2）切一張字幕列，**畫面沒變的不 OCR**（約省 40%）；可用 `--start`／`--end` 只跑一段。輸出 `{秒數: 文字}`。
   - **分段（超過 30 分鐘自動啟動）**：每 10 分鐘一段，各自存成 `<out>.segs/seg_<起始秒>.json`（原子寫入）；中斷或重開機後**重跑同一個指令**就會跳過已完成的段落；全部完成才合併成 `--out`，缺段時不寫 `--out` 並列出缺哪些。`--segment-min N` 改段長，`--segment-min 0` 強制一次跑完，`--auto-segment-min` 改門檻，`--seg-dir` 改段落資料夾。要重做某一段就刪它的 `seg_*.json`。續跑前會比對 `plan.json` 記的參數（影片、`--model`、`--every`、`--crop`、`--start`、`--end`），不同就拒絕（結束碼 2），避免把不同設定的段落混在一起合併；要換參數請用新的 `--out`，或刪掉 `.segs` 資料夾。`--segment-min 0`（一次跑完）不寫段落，給 `--seg-dir` 會被忽略並印警告。
   - **進度**：每段結束印一行（`[seg 3/8] 0:20:00-0:30:00 done: 200 samples, 58s`）；`python scripts/subtitle_ocr.py status ocr.json` 列出完成／剩餘／進行中的段落與距上次完成多久。
   - **低負載與脫離 session**：`--low-priority` 把辨識程序降到 Idle 優先權；`--background` 另起脫離 session 的程序（隱含低優先權），log 寫到 `<seg-dir>/progress.log`、本程序立刻返回。關掉終端機或 Claude 不會中止它，關機會；重開機後重跑同一個指令即可續跑。
   - **兩個程序**：每段用 `.lock` 搶占，同時跑不會辨識同一段，過期的鎖自動接手：同一台機器只看程序還在不在（段落跑超過 30 分鐘也不會被搶），不同機器才看鎖超過 30 分鐘；`status` 不會把死鎖當成執行中；但 onnxruntime 本身已用多核心，筆電上兩個程序比單程序**更慢**（實測每段 60 秒 vs 兩個程序各約 165 秒），所以預設用單程序（`--workers 1`）。先做完的程序若看到還有段落在別的程序手上，會印提示並以非 0 結束，等另一個完成後重跑同一指令即合併。
4. `python scripts/subtitle_ocr.py compare <資料夾> --ocr ocr.json [--thr 0.85]`：字幕先簡轉繁，相鄰相似的合併成事件，逐字稿每行用 `difflib` 算被字幕涵蓋的比例，低於門檻的列出「逐字稿／字幕／比例」，人工逐段讀。
5. 人工判斷差異，整理成替換表（含上下文，避免誤傷）批次套用到 `transcript.md`，每段改完就 commit。
6. 摘要、投影片說明與 `meta.json` 裡出現的錯誤名稱要一併更新；`known_asr_errors` 記錄「字幕確認」與仍不確定的處理。

實測（楞嚴經第103集 03:00–08:00，150 張字幕列）：`run` 實際只 OCR 85 張，6 個程序約 4 分鐘；`compare` 在門檻 0.7 標出 8 行，都是 OCR 同音雜訊或時間對不齊。

## 注意事項

- OCR 單張 v4 約 1–2 秒、v5 約 4–5 秒（CPU）；v5 全片要分段低負載跑（`--workers 1 --every 3 --background`，第104集 72 分鐘約一小時），v5 讀出的字之間可能夾空格，比對時已忽略。字幕變化不頻繁時，可只取字幕變化的畫面，約省一半時間。
- **慢的時候先看 `progress.log` 的 `[trace]` 行**：開頭行有 pid、優先權、CPU 數、模型與電源狀態（`power AC 88%`／`power battery 62%`），每 10 張一行平均與最慢秒數。筆電用電池時 CPU 被功耗限制，同一批畫面每張從約 4 秒變成 11–35 秒（第097集實測），看起來像卡住；請接上電源再跑，長片尤其要接電源。
- 比對腳本的「涵蓋比例」對短行、時間重疊行會誤報，低於 0.85 的行不必全部有問題。
- 暫存檔（`sub/` 圖片、OCR JSON、venv）放暫存區，不要進 repo；影片檔不入庫。
- Bash 的 `rm` 展開變數會被安全檢查擋，清暫存時改用字面路徑或 `"${VAR:?}"` 寫法。

## 可以改進的方向

- 已完成（`scripts/subtitle_ocr.py`）：判斷有無燒入字幕（`probe`）、只對變化的畫面 OCR（`run`）、長片自動分段可續跑、低優先權與背景執行、進度（`status`）、輸出逐字稿 vs 字幕差異清單（`compare`）。
- 尚未做：`watch_archive.py` 歸檔時自動 `probe` 並提示；OCR 引擎自動安裝。
- 沒有字幕的影片：退回「Groq 兩次轉錄互補」；補漏遇 429 時，單獨重送缺漏段（見 `whisper.py` 的補漏流程與 issue #12／#13）。
